### Путь в две линии (решения 30.10)

30.10 вы решили: не больше двух потоков одновременно, задачи, которые можно, объединить, и не перетестировать каждый шаг. Сначала было решено идти строго по одной задаче, потом — двумя линиями. Линии не пересекаются по модулям: вторая берёт подготовку, Админку и задачи тех модулей, которые первая уже прошла.

- Правила:
	- в работе не больше двух задач — по одной в каждой линии; следующая задача линии начинается сразу после слияния предыдущей, без ожидания команды;
	- задачу делает поток, чей это модуль: у него наработки и память по модулю; остальные потоки в это время стоят;
	- одна задача (Issue) — один PR, ветка — от свежего main;
	- проверки — по одному разу: во время работы — тесты своего модуля; перед PR — один раз `pnpm check`; сквозные тесты — только в CI; spec-reviewer и security-reviewer — по одному проходу, повторный — только если нашли критичное;
	- если обе линии меняют базу, PR с миграцией сливаются по одному: второй ждёт первого, обновляет ветку слиянием и пересоздаёт свою миграцию;
	- после слияния поток пишет одну строку в «П: Общий план и статус задач» и передаёт работу следующему в своей линии;
	- с 31.10 (ваше решение, в правилах продукта — PR #148, docs/decisions.md п. О-2): если ТЗ и прототип расходятся или есть вопрос — делать как в прототипе, без вопроса к вам; то, чего в прототипе нет и что работает только на сервере, — по ТЗ; защита — по более строгому из ТЗ и прототипа; расхождение по-прежнему записывается в docs/deviations.md; к вам — только критичный вопрос, который без вас не решить, с push-уведомлением.
