# Этап 2 — задачи в порядке выполнения

Составлено 27.10.2026 в треде «П: Архитектура и план разработки» по ТЗ (spec/ТЗ Buhuchet.kg.md), прототипу v58 (spec/prototype) и плану разработки. Сессия разработки одна, поэтому потоки идут по очереди. Порядок ниже учитывает зависимости, а не буквы потоков.

## Как читать

- Задачи заведены в Issues kutya001/Buhuchet.kg 27.10.2026: номер Issue = 56 + NN (2.01 → #57 … 2.43 → #99); в заголовках он указан в скобках.

- «п. N» — N-й пункт раздела ТЗ «Как проверить, что всё работает»; первый пункт этого раздела — п. 1. Полный текст пункта переносится в задачу из ТЗ как есть.
- «Таблицы» — спроектированные таблицы из DevBuhUchet.kg/db/schema.json. Имена в схеме — черновик: правильные имена задаёт код, схему потом сверяю я.
- Каждая задача — один кусок модуля, одна ветка, один PR. Шаблон задачи — .github/ISSUE_TEMPLATE/task.yml.
- Кроме пунктов приёмки, у каждой задачи есть свои проверки «(проверка задачи …)» в docs/acceptance-map.md, как в этапе 1.
- Где задача опирается на модуль, которого ещё нет, она делает только свою часть. Вкладку или кнопку будущего модуля она не показывает, а не рисует заглушку. Исключение — то, что прямо названо в «Входит».
- Миграции идут по очереди, по одной задаче за раз (CLAUDE.md).
